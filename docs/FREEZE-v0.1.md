# WGIF v0.1.0 freeze checklist (release gate)

**Status:** candidate checklist for Lumi and the lane owners; **not approval to merge or tag**. Based on `dev` at `50c5a7e` and Nova's PR #5 review by Ace. The *file-format* manifest version is `"wgif": "0.1"`; `v0.1.0` is the *Git/software release tag* (semver). No `"wgif": "0.1.0"` or `"wgif": "0.1.1"`.

## Required before tagging

- [ ] **Owner decision:** Stephon approves the v0.1 normative contract, license/release scope, destination branch, and tag. No silent schema edits after this freeze; changes to the format thereafter need a documented new format revision.
- [ ] **Normative docs:** reconcile `docs/SPEC-v0.1-draft.md`, `docs/CAPABILITIES.md`, all five JSON Schemas, `types.ts`, and implementation. Incorporate the completed Q5 model answer in the spec's review section. Keep `requiredExtensions[]` absent. Replace draft/RC language with final wording **only after** approval; historical proposals may remain labelled historical.
- [ ] **Capability behavior:** the court declares `requires: ["scene.glb", "runtime.rules"]`; the player advertises only implemented capabilities (`scene.glb`, `interaction.camera`, `runtime.rules`), never general `runtime.onnx` for the specialized JS MLP. Test unknown/unsupported `requires[]` yields a named refusal and (where implemented) preview fallback. Ensure optional ONNX failure uses same-purpose rules fallback without bypassing ZIP/hash/schema validation.
- [ ] **Offline acceptance:** demonstrate the player working with network disconnected using an installed PWA *or an explicitly documented equivalent local application*. Direct `file://` is not required. A hosted HTTP(S) page that stops working offline does not satisfy the v0.1 player requirement. The `.wgif` must not trigger external asset/model/code fetches.
- [ ] **Format/security:** confirm the archive preflight enforces 256 entries / 16 MiB entry / 64 MiB uncompressed total; 1 MiB manifest and declarative JSON caps remain. Test unsafe ZIPs, traversal, duplicate paths, invalid hashes, external GLB URIs, executable payloads, bad model descriptors/fallbacks, and signing/canonicalization. Audit the glTF `extensionsRequired` ↔ `requires[]` contract (the hardened validator currently checks external URI references but does not itself fully validate all glTF extension dependencies); either enforce this in the reader/player or explicitly document and test the chosen responsibility before freeze.
- [ ] **Examples/reproducibility:** rebuild both `examples/court/court.wgif` and generated `court.gen.wgif` using release tooling; validate both with compiled `wgif validate`, inspect warnings, and prove deterministic output by comparing generated bytes to committed artifacts. Replace legacy `0.1-draft` payload versions if any remain in shipped files; unsigned editable examples may correctly report `signature: absent`.
- [ ] **CI/release smoke:** clean install; lint; all workspace and scripts typechecks; full tests (including malformed archive corpus and fallback cases); all builds; `size:report --strict`; compiled CLI `validate/inspect/pack/sign` smoke. Test the actual player in a browser, including rules NPC and unsupported-capability refusal. Test integrity/signature after pack/repack. Green unit tests alone do not verify offline behavior or the renderer.
- [ ] **Package versions/lock:** change `@wgif/format` and `@wgif/ai` from `0.1.0-draft.0` to `0.1.0`, update `package-lock.json` via npm (do not hand-edit version references), then rerun `npm ci` and all CI gates. The private monorepo root can remain `0.0.0` if intentionally unversioned; document that choice. Preserve manifest `wgif: "0.1"`.
- [ ] **Release commit/tag:** ensure `LICENSE`, docs, published artifact/export paths, SHA-256 sums of example `.wgif` files, and release notes match the exact release commit. Freeze from the approved release commit only; tag `v0.1.0` after the full gate passes. Do not automatically merge/tag.

## Not v0.1 blockers by themselves

- General-purpose ONNX, arbitrary user-supplied ML graphs, a larger-than-1 MiB **optimization target**, embedded WASM/scripts, and direct `file://` browser startup are **not** requirements for v0.1.
- A specialized JS MLP can be shipped as an optional optimization without advertising `runtime.onnx`; the default rules-only court is valid.
- A signed world can be cryptographically valid while its creator remains unverified; a key registry/PKI is not required.
