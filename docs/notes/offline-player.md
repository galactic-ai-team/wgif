# Offline player (Phase One item 6)

The player is a PWA: a hand-written service worker plus a web manifest,
both built by the Vite build, no new runtime dependencies.

## What ships

- `apps/player/src/sw.ts` — the worker source. It has no imports: the
  `offlinePrecache` Vite plugin (`apps/player/vite-offline.ts`) only
  replaces two placeholders in the emitted file, in `writeBundle` (after
  every dist file is written, so the precache list is the true dist
  listing): the versioned cache name
  (`wgif-player-v<player version>`, from `apps/player/package.json`) and
  this build's precache list. The worker lives at `dist/sw.js` (fixed name
  — its scope is its own directory) via a second Rollup input in
  `vite.config.ts`; every other entry keeps the hashed asset name.
- `apps/player/public/manifest.webmanifest` — name, `display: standalone`,
  `start_url: ./`, theme color, and 192/512 PNG icons in `public/icons/`
  (generated by `scripts/gen-pwa-icons.mjs`, pure Node, no image dep).
  The shell links it from `index.html`.
- `apps/player/src/main.ts` registers the worker in production builds only
  (`import.meta.env.PROD`), so `vite dev` never caches dev assets. A failed
  registration only logs a warning; the player keeps working online-only.

## Behaviour

- **Install:** precaches the whole dist — the app shell (`./` and
  `./index.html`), the manifest, the icons and `samples/court.wgif` —
  then `skipWaiting()`. Navigations always resolve to the cached shell,
  so an offline reload works even for a path that was never precached.
- **Activate:** deletes older `wgif-player-*` caches, then `clients.claim()`.
- **Fetch:** precached URLs are served **cache-first** (a reload with the
  network off makes zero network requests); any other same-origin GET is
  network-first with a cache fallback, and is cached for next time.
  Cross-origin requests are never intercepted. A bump of the player version
  rotates the cache name; even without a bump, a changed `sw.js` reinstalls
  and re-precaches.

## Why hand-written, not vite-plugin-pwa

The lane allows no new runtime dependencies. vite-plugin-pwa would pull
workbox-window into the player bundle at runtime; the hand-written worker
adds ~2 KB to dist and nothing to the app bundle.

## Checks

- `apps/player/test/offline.test.ts` (vitest, runs in CI): the cache-name
  and precache-list builders, the worker source (no imports, placeholders,
  lifecycle, cache-first), the manifest + icons, the shell wiring, the
  dependency guard, and Dee's pixel-ratio cap pinned.
- `apps/player/scripts/check-offline.mjs` (runs on every `npm run build` in
  the player): validates the built dist — `sw.js` has the versioned cache
  name and no placeholders, the precache list covers every dist file, the
  manifest parses and its icons exist, the shell links the manifest.
- Browser re-check (Playwright, Chromium): load online, wait for the
  worker, go offline, reload — the shell and the sample court load, every
  response is served from the worker, zero requests hit the network. See
  the lane's delivery message for the measured result.

## What it is not

No background sync, no push, no install-prompt handling beyond the
manifest, and no offline support for user-opened `.wgif` files that were
never cached (they come from the file picker, not the network, so they
already work offline). The real-device check (phone + desktop, network
off) is still open — PHASE1 exit check.
